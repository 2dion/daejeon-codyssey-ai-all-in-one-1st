## 1. MAC 연산과 AI에서의 중요성

**정의.** MAC(Multiply-Accumulate)은 곱한 값을 누적 변수에 더하는 한 단계 연산이다. 두 배열의 같은 위치끼리 이것을 반복하면 점수 하나가 나온다. 수학적으로는 두 배열을 길게 편 벡터의 내적과 같다.

```text
score = Σ Σ pattern[i][j] × filter[i][j]
```

**왜 중요한가.** 신경망의 뉴런 하나는 입력마다 가중치를 곱해 모두 더한 뒤(MAC) 활성화 함수를 한 번 씌운다. 입력이 1,000개면 MAC은 1,000번, 활성화는 1번이다. 층은 뉴런 수백 개, 합성곱(CNN)은 필터를 이미지 위 모든 위치로 옮기며 MAC을 반복하므로 AI 계산량의 대부분이 MAC이다.

**예제.** 입력 [0.5, 1.0, 0.2], 가중치 [0.8, -0.3, 1.5]이면 0.5×0.8 + 1.0×(-0.3) + 0.2×1.5 = 0.4다.

**계산하는 칩.** 같은 MAC을 수없이 반복하는 일에 맞춰 칩이 나뉘었다.

| 칩 | 설계 방향 | 잘하는 일 |
| --- | --- | --- |
| CPU | 강한 코어 몇 개가 복잡한 명령을 순서대로 | 분기가 많은 일반 프로그램, 운영체제 |
| GPU | 단순한 코어 수천 개가 같은 계산을 동시에 | 그래픽, 행렬 연산, AI 학습 |
| NPU | MAC 유닛 배열 + 칩 안 메모리 + 낮은 정밀도 | 적은 전력으로 하는 AI 추론(휴대폰, 노트북) |

## 2. 곱하고 더해 유사도를 재는 원리

**정의.** 필터는 판별할 모양을 숫자 배열로 정의한 것이고, 각 칸의 값은 "그 칸을 얼마나 중요하게 볼지"를 나타내는 가중치다. 입력 패턴과 필터의 MAC 점수가 클수록 두 모양이 비슷하다고 본다.

**왜 점수가 유사도인가.** 곱이 0이 아닌 칸은 패턴과 필터 모두에 값이 있는 칸뿐이다. 두 모양이 많이 겹칠수록 더해지는 항이 늘어 점수가 커진다. 필터에서 0인 칸은 입력이 무엇이든 점수에 영향이 없다.

**예제.** 3×3 십자가 입력을 두 필터에 대 본다.

| 입력 | 십자가 필터 점수 | X 필터 점수 | 판정 |
| --- | --- | --- | --- |
| 십자가 (1이 5칸) | 5 (5칸 겹침) | 1 (가운데만 겹침) | 십자가 |
| X (1이 5칸) | 1 | 5 | X |
| 모든 칸이 1 | 5 | 5 | 동점 |

**한계.** 내적은 필터 가중치의 크기에 영향을 받는다. 모든 칸이 1인 입력은 점수가 가중치 합이 되고, 한 칸에 큰 가중치를 몰아 둔 필터는 다른 모양에도 높은 점수를 줄 수 있다. 그래서 벡터 길이로 나눠 방향만 비교하는 코사인 유사도, 다른 칸 수를 세는 해밍 거리(0/1 패턴용) 같은 다른 척도도 쓴다.

## 3. 키 규칙·라벨 규칙과 정규화

**정의.** 키 규칙은 데이터의 이름이 따르는 형식이고, 라벨 정규화(표준화)는 같은 뜻의 여러 표기를 하나의 표준 라벨로 맞추는 일이다. 통계의 정규화(값의 범위를 맞춤)와는 다른 뜻이다.

| 대상 | 규칙 | 예 | 읽는 법 |
| --- | --- | --- | --- |
| 필터 키 | `size_{N}` | `size_13` | 크기 13의 필터 묶음 |
| 패턴 키 | `size_{N}_{idx}` | `size_13_2` | 크기 13, 그 크기의 2번째 케이스 |
| 필터 라벨 | `cross`, `x` | `cross` | 표준 라벨 Cross |
| 정답 라벨 | `+`, `x` | `+` | 표준 라벨 Cross |

**왜 필요한가.** 표기가 다르면 문자열 비교가 실패한다. `'+' == 'cross'`는 거짓이라, 맞게 판정해도 FAIL이 된다. 데이터를 읽는 입구에서 한 번 표준 라벨로 바꾸면, 그 뒤의 판정·출력·비교는 라벨 두 개만 알면 된다. 규칙이 한 곳에 모여 있어 새 표기가 생겨도 대응표 한 줄만 고친다.

**예제.** 공백과 대소문자를 맞춘 뒤 대응표에서 찾고, 모르는 라벨은 조용히 넘기지 않고 오류로 알린다.

```python
ALIASES = {"+": "Cross", "cross": "Cross", "x": "X"}

def normalize_label(raw):
    key = raw.strip().lower()
    if key not in ALIASES:
        raise ValueError(f"알 수 없는 라벨: {raw}")
    return ALIASES[key]
```

## 4. 부동소수점 오차와 epsilon 비교

**정의.** 부동소수점(floating point)은 수를 "유효숫자 × 2의 지수"로 저장해 소수점 위치를 옮기는(떠다니는) 방식이다. 0.1처럼 2진수로 끝나지 않는 수는 64비트에 맞춰 반올림되므로 아주 작은 오차가 생긴다. 허용오차(epsilon, ε)는 "이만큼의 차이는 같다고 본다"는 기준값이다.

```python
>>> 0.1 + 0.2
0.30000000000000004
>>> total = 0.0
>>> for _ in range(9): total += 0.1
>>> total
0.8999999999999999
```

**왜 판정에 영향을 주나.** 수학적으로 같은 두 점수(0.9와 0.1×9)가 끝자리만 다르게 나오면, `==`나 `>` 비교는 덧셈 순서 같은 우연에 따라 한쪽을 고른다. 표시는 확신에 찬 판정인데 실제로는 구분할 근거가 없는 상황이다.

**비교 정책.** 두 점수 차이의 절댓값이 허용오차보다 작으면 동점으로 본다. 이 규칙을 한 곳에 정해 모든 판정에 똑같이 쓰기 때문에 "정책"이라 부른다.

```python
EPS = 1e-9
if abs(a - b) < EPS:
    result = "동점"
elif a > b:
    result = "A"
else:
    result = "B"
```

**기준값 고르기.** 누적 오차(보통 1e-16 ~ 1e-15)보다 충분히 크고, 의미 있는 점수 차이(예: 0.1)보다 충분히 작게 잡는다. 너무 크면 진짜 차이도 동점이 되고, 너무 작으면 오차를 흡수하지 못한다. 값의 크기가 들쭉날쭉하면 상대 허용오차도 함께 보는 `math.isclose()`를 쓴다.

## 5. 시간 측정과 O(N²)

**정의.** 시간 복잡도는 입력 크기 N이 커질 때 연산량이 늘어나는 모양을 Big-O로 나타낸 것이다. 상수 배는 지운다. N×N 배열의 MAC은 칸 N²개를 한 번씩 방문하므로 **O(N²)**이고, 필터가 2개여서 2N²번이어도 O(N²)이다. 메모리를 보는 공간 복잡도는 배열 저장이 O(N²), MAC 계산 중 추가 메모리는 누적 변수 하나라 O(1)이다.

| 크기 | 연산 횟수(N²) | 3×3 대비 |
| --- | --- | --- |
| 3×3 | 9 | 1배 |
| 5×5 | 25 | 약 2.8배 |
| 13×13 | 169 | 약 19배 |
| 25×25 | 625 | 약 69배 |

**왜 측정하나.** 연산 횟수는 이론이고, 측정은 그 이론이 실제로 맞는지 보는 근거다. N을 2배로 늘릴 때 시간이 약 4배(= 2²)가 되면 O(N²)을 뒷받침한다.

**제대로 재는 법.**

- 입력, 파일 읽기, 출력(I/O)은 측정 구간 밖에서 끝내고, 연산 함수 호출 앞뒤만 잰다.
- 짧은 구간은 고해상도 시계 `time.perf_counter()`로 재고, 초 단위를 1000배해 ms로 바꾼다.
- 한 번은 잡음이 커서 10회 이상 반복해 평균을 낸다. 첫 호출은 버리는(워밍업) 경우도 많다.
- 작은 N에서는 함수 호출 같은 고정 비용 때문에 시간 배율이 N² 배율보다 작게 나오기 쉽다. 추세는 N이 클 때 본다.

## 6. 실패 원인 세 갈래 진단

**정의.** 테스트가 틀렸을 때 원인을 데이터/스키마, 로직, 수치 비교 세 갈래로 나눠 찾는 방법이다. 스키마는 데이터가 따라야 하는 구조(키 이름, 타입, 크기)다.

| 갈래 | 생기는 상황 | 확인 방법 | 고치는 곳 |
| --- | --- | --- | --- |
| 데이터/스키마 | 키 규칙 위반, 표기 차이, 행·열 개수 불일치, 문자열 숫자, 필수 키 누락 | 계산 전에 모양·타입·키를 검증하고 원인을 메시지로 남김 | 데이터 수정, 정규화 규칙 추가 |
| 로직 | 행과 열을 바꿔 씀, 누적 변수를 반복 안에서 초기화, 다른 크기의 필터 선택 | 손으로 계산할 수 있는 작은 예(3×3)와 기대값 비교 | 코드 수정, 테스트 추가 |
| 수치 비교 | 수학적으로 같은 점수가 1e-15 수준만 다름 | 두 점수의 차이를 출력해 크기를 본다 | epsilon 비교 정책, 필요하면 데이터(가중치) 재설계 |

**왜 순서가 중요한가.** 데이터가 틀리면 로직이 맞아도 결과가 틀리므로 스키마를 먼저 걸러야 한다. 로직이 맞다는 것을 확인한 뒤에야 남은 차이를 수치 오차로 볼 수 있다. 순서를 지키면 원인이 섞이지 않는다.

**예제.** 어떤 케이스가 동점으로 FAIL이고 두 점수 차이가 2.7e-15다. 스키마는 정상이고 다른 케이스는 맞으니 로직도 아니다. 그러면 수치 비교 문제이고, 더 들여다보면 필터 가중치가 두 점수를 같게 만드는 설계인 경우가 많다. 판정 규칙을 바꿔 PASS를 만들면 문제를 숨기게 된다.

## 목표 점검표

각 항목을 문서를 보지 않고 1분 안에 말로 설명할 수 있으면 체크한다.

- [ ] MAC이 무엇이고, 신경망 계산의 대부분이 왜 MAC인지 뉴런 예로 설명할 수 있다.
- [ ] CPU와 NPU가 MAC을 처리하는 방식의 차이를 말할 수 있다.
- [ ] 점수가 클수록 비슷하다고 보는 이유와 내적의 한계를 3×3 예로 보여 줄 수 있다.
- [ ] `size_{N}_{idx}` 키에서 N을 꺼내 필터를 고르는 규칙을 설명할 수 있다.
- [ ] 라벨을 입구에서 한 번 표준화하는 이유를 말할 수 있다.
- [ ] 0.1 + 0.2가 0.3이 아닌 이유와 epsilon 비교가 필요한 이유를 말할 수 있다.
- [ ] epsilon을 너무 크게 또는 작게 잡을 때 생기는 문제를 말할 수 있다.
- [ ] MAC이 O(N²)인 근거를 연산 횟수와 측정 결과로 연결할 수 있다.
- [ ] 측정에서 I/O를 빼고 반복 평균을 내는 이유를 말할 수 있다.
- [ ] 실패를 세 갈래로 나눠 어떤 순서로 확인하는지 설명할 수 있다.
